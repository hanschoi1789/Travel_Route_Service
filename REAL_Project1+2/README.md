# 여행 장소 선정

여행 조건과 취향을 입력하면 카카오에서 후보를 찾고, Google 평점·평가 수·영업시간을 확인해 최종 방문 장소를 정합니다. 메인 여행지와 서로 다른 식당 2곳을 포함합니다. 방문 순서와 이동시간은 다음 경로 계산 단계에서 정합니다.

**경로 계산에 넘길 파일은 이 폴더의 [final_places.csv](final_places.csv)와 [route_input.json](route_input.json)입니다.** [전달 파일 안내](00_전달파일_안내.md)에 실행 날짜와 확인할 사항을 정리했습니다. 이 두 파일을 읽는 데에는 API 키가 필요하지 않습니다.

## 실행

`run.cmd`를 더블클릭합니다. 처음에는 필요한 패키지를 설치합니다. Python 3.11 이상이 필요합니다.

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

화면에서 여행 조건 입력 → **메인 여행지 검색** → 검색 결과의 지점 선택 → **여행 장소 추천** 순서로 진행합니다. 최종 장소는 자동으로 결정됩니다. 점심과 저녁을 모두 포함하므로 두 식사 시간대를 포함한 하루 일정을 입력합니다.

키는 `.streamlit/secrets.toml`의 `KAKAO_REST_API_KEY`, `GOOGLE_PLACES_API_KEY`에 설정합니다. 저장소와 전달용 압축 파일에는 키가 없으므로 `.streamlit/secrets.example.toml`을 같은 폴더의 `secrets.toml`로 복사해 설정하면 됩니다.

## 선정 기준

1. 기존 후보 구성 코드로 취향·반경에 맞는 장소를 추립니다.
2. 장소명·주소·좌표를 대조해 Google의 같은 지점을 찾습니다. 연결이 불확실하거나 폐업·휴업인 곳, 여행 시간 안에 체류할 수 없는 곳은 제외합니다.
3. 메인 장소와 점심·저녁을 배치할 수 있는 서로 다른 식당 2곳을 포함합니다. 카페·빵집·술집은 식당 수에 넣지 않습니다. 식사 시간은 점심 11:00~14:30, 저녁 17:00~19:30, 체류 60분으로 잡았습니다. 부족한 식당 후보는 같은 반경에서 보충하며, 보충 후보는 식사 두 자리에만 사용합니다.
4. 조건을 만족하는 집합 중 **영업시간이 확인된 장소 수 → 평가가 있는 장소 수 → 보정 평점 합계** 순으로 비교합니다. 동률이면 평가 수, 장소 ID 순으로 결정합니다.

보정 평점은 `(평가 수 × Google 평점 + 20 × 후보 평균 평점) / (평가 수 + 20)`입니다. 평가가 몇 개 없는 5점 장소가 과도하게 유리해지는 것을 줄이기 위한 기준입니다. 20은 설계값이며 학습한 계수는 아닙니다. 이전의 조합 점수(추천점수·용도 중복·거리 감점)는 최종 선정에서 사용하지 않습니다.

영업시간이 없는 일반 장소는 ‘확인 필요’로 남기고, 시간이 확인된 후보를 먼저 고릅니다. 필수 식당 2곳은 식사 시간대의 영업시간이 확인되어야 합니다. 필수 장소가 휴무이거나 식당 조건을 충족하지 못하면 성공 결과를 만들지 않고 이유를 표시합니다.

## 전달 파일

폴더 맨 위에 이번 전달본을 두었습니다. `handoff_manifest.json`에 조회 시각·여행 조건·원본 실행 폴더와 파일 검증값을 기록했습니다.

- `final_places.csv`: 최종 장소, 카카오 좌표, 필수 여부, Google 평점·평가 수, 영업시간, 선정 근거
- `route_input.json`: 체류시간, 영업 구간, 도착 가능 구간, 점심·저녁 후보 시간대

이 파일들은 전달 당시의 결과입니다. 프로그램을 새로 실행한 결과는 `outputs/latest.json`에서 성공 여부와 실행 폴더를 확인합니다. `python scripts/package_handoff.py`를 실행하면 최신 성공 결과로 폴더 맨 위의 전달본과 ZIP을 함께 갱신합니다.

각 실행 폴더의 `not_selected_places.csv`에는 제외 이유가, `selection_result.json`에는 후보 비교 결과가 들어 있습니다. 시간 단위와 필드는 [ROUTE_INPUT.md](ROUTE_INPUT.md)에 정리했습니다.

## 코드와 확인할 점

`app.py`는 후보 구성부터 최종 선정까지 들어 있는 통합 코드입니다. `selector.py`에는 Google 장소 연결, 영업시간 처리, 최종 선정만 따로 담았습니다. 저장된 후보로 다시 조회하려면 `run_console.cmd`를 실행하면 됩니다.

영업시간은 요청일부터 7일 이내이면 날짜별 정보, 그 이후이면 평소 요일별 정보를 사용합니다. 실제 이동시간·휴일 변경·예약·마지막 주문까지 보장하는 결과는 아닙니다. 리뷰 본문은 화면에서 따로 조회할 수 있으며, 제공되는 최대 5개 리뷰로 전체 이용자의 감정을 추정하지 않습니다. 별도 모델 학습은 이번 최종 선정에 포함하지 않았습니다.

Google 응답을 재사용하는 디스크 캐시는 만들지 않습니다. 산출물은 해당 실행의 전달 자료이며, 여행 날짜가 바뀌면 다시 조회합니다. 공유용 압축 파일에는 키·가상환경·리뷰 본문을 넣지 않습니다.

API 문서: [Google Places](https://developers.google.com/maps/documentation/places/web-service/place-details), [영업시간 필드](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places), [표시·출처 안내](https://developers.google.com/maps/documentation/places/web-service/policies).
